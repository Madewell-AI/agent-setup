# Memory System

## Overview

The agent uses a 4-layer memory system that gives it persistent knowledge across sessions:

1. **MEMORY.md** — Durable operating knowledge (always loaded)
2. **Daily Notes** — Auto-generated summaries of each day's activity
3. **Knowledge Graph** — Structured facts about projects, people, and areas (PARA method)
4. **Session Notes** — Detailed notes from significant conversations

## How It Works

### Auto-Recall (Claude Code)

On Claude Code, the `UserPromptSubmit` hook fires before every response. It:
1. Extracts key terms from your message
2. Searches all 4 memory layers for matching content
3. Injects relevant context into the session

This means the agent automatically "remembers" relevant information without you having to remind it.

### Auto-Recall (Codex CLI)

Codex CLI doesn't have a per-message hook, so auto-recall is handled via an instruction in AGENTS.md that tells the agent to run the recall script before responding. This is ~90% as reliable as the hook-based approach.

Codex also has its own built-in memory system that automatically extracts and consolidates memories from conversations.

### Nightly Consolidation

A cron job runs nightly to:
1. Review the day's conversations
2. Write a daily note summarizing key events
3. Update the knowledge graph with new durable facts
4. Archive completed sessions

## Layer Details

### MEMORY.md
Location: `~/.claude/projects/-home-USER/memory/MEMORY.md` (Claude Code) or `~/memory/MEMORY.md` (Codex)

Contains:
- User preferences and working style
- System architecture notes
- Key paths and credentials references
- Operational rules

### Daily Notes
Location: `~/memory/YYYY-MM-DD.md`

Auto-generated by the nightly cron job. Contains:
- Timeline of the day's events
- Open loops / unfinished items
- Context to carry forward

### Knowledge Graph
Location: `~/life/`

PARA method structure:
- **Projects** — Active projects with goals and deadlines
- **Areas** — Ongoing responsibilities (companies, people, operations)
- **Resources** — Reference material
- **Archives** — Completed/inactive items

Each entity has:
- `summary.md` — Narrative overview
- `items.json` — Atomic facts

### Session Notes
Location: `~/sessions/YYYY-MM-DD-slug.md`

Written during or after significant conversations. Not auto-generated — the agent creates these when a conversation contains important decisions, research, or context worth preserving.

## Teaching Your Agent

The more you use the system, the smarter it gets:
- It learns your preferences from corrections
- It tracks project context from conversations
- It builds up knowledge about your tools, workflows, and team

To explicitly teach something: just tell your agent "remember that..." or "from now on, always..." and it will update the appropriate memory layer.
